## 为什么交付目录大

以下是完整重建后的工作树，而不是 Git 仓库下载量、邮件压缩包或游戏安装包。测量绑定到技术候选提交 `3c368437dd9df0f7a4589ce3e8f452bf7de1e164`，未修改任何模型。

完整树8038文件（8032资产+6辅助），3,509,029,574字节；其中PNG约2.448 GB、Blend约666 MB、FBX约355 MB。仅名为 previews 的文件夹内PNG就1.064 GB。源树保留图册素材、重复外置纹理、独立版本和组合场景，因此不能按其大小估算游戏资源。

全文件SHA-256去重测得额外同内容副本约1.076 GB。textures/ProjectFiles路径中PNG共1.209 GB，重复额外副本约1.044 GB。这里只是可研究的存储机会，没有删除或重定位文件。

实际只读打开101个Blend后，1473个嵌入PNG引用载荷共480,505,406字节，仅326种独立内容，共162,560,592字节；全部均能在外置PNG找到完全相同字节。分辨率引用数：4096²×188、2048²×613、1024²×283、512²×389。它们包含跨版本与组合场景重复，不等于1473种游戏纹理或显存占用。

例如HarperCourtyardAssembly是组合源场景，143,044,779字节，87嵌入图像引用（58×4K+29×1K），载荷131,767,983字节，但仅22种不同图像、56,335,972字节。不能将这个源场景称为单栋建筑游戏文件。嵌入载荷可能受Blend压缩，不可把上述机会简单相加。

证据：[汇总](size-summary-20261118.json)、[逐源嵌入图片尺寸/字节/SHA](packed-image-inventory-20261118.json)。图片记录由Blender读取 packed_file.data、size，再计算SHA-256；文件统计遍历重建完整树并按字节SHA分组。

## 安全的后续优化顺序
1. 作者源包、预览文档、候选导入包分开交付；为每个建筑明确优先版本和依赖，避免把组合场景/历史版本一起装进游戏。
2. 在新工作副本中试做按内容哈希存储的共享外置纹理库，输出时再按官方命名恢复；保留完整清单和校验。不直接删除当前路径，避免破坏相对路径、离线打开或恢复链。
3. Blend内共享图像数据块只能在检查颜色空间、alpha模式及节点引用后试验。同字节不同语义不能盲目合并。
4. 4K降2K会减少75%像素，但会损失细节；先做近远景对照与实际Editor测试。不能为压缩包小而全局降面/降纹理。
5. 源文件共享不证明CS2运行时共享。实际编译包、GPU压缩格式/mipmap、显存、载入时间与批处理须在Editor/游戏测量，目前均未证实。

## 可逆的无损交付去重工具

`content_bundle.py` 将完整源工作树打成内容寻址ZIP：相同SHA-256文件内容只保存一次，manifest记录每一个原路径、字节数和SHA。不降面、不降纹理、不改Blend、不删除输入。需要Python标准库，无新增第三方依赖。

```sh
python maintenance/content_bundle.py pack ../Campus_Candidate_Technical ../Campus_Source_ContentBundle.zip
python maintenance/content_bundle.py unpack ../Campus_Source_ContentBundle.zip ../Campus_Source_Restored
```

源目录必须完整且不在写入中；压缩包必须是源树外的新路径，恢复目录必须不存在。脚本拒绝路径穿越、重复/大小写冲突路径、符号链接源和对象校验不符。恢复前验证全部内容，再逐路径写入并复验SHA；磁盘不足预检会拒绝，其他中途错误可能留下未完成的新目录，不能当作验收成功。准备充足磁盘空间，恢复本样本至少需3.51GB，另保留压缩包占用。源文件字节及相对文件路径精确保留，不承诺时间戳、权限、空目录或特殊文件。

这种ZIP不是普通“解压即用”布局：直接解压只得到objects和manifest，必须用上述unpack恢复原文件名。相同PNG在不同Blend内部的重复并不由这个文件级工具消除；旧恢复链仍作为权威可重复来源保留。此工具仅优化作者交付存储，不生成游戏包。

### 完整样本实测
同样8038文件、同为ZIP Deflate level 6：普通逐路径ZIP **3,388,234,325字节**，内容寻址ZIP **2,364,424,822字节**，少 **1,023,809,503字节（30.22%）**。已实际恢复全部文件并与原树逐路径/SHA比较一致。不是拿未压缩原树和压缩新包作不公平比较，也不是与只含部分场景的邮件增量包比较。两份实验ZIP保留在云工作区，未上传到Git仓库；仓库包含可复现工具与[实测回执](content-bundle-experiment-20261118.json)。

### 持久保存与重建输入
2.364GB实验包尚未上传到Library或Release，**不能称为已永久交付下载包**。PR持久保存工具、[完整8038路径/大小/SHA清单（gzip JSON）](content-bundle-manifest-20261118.json.gz)及回执；可依完整恢复链重新制作。清单是内容校验依据，ZIP文件时间戳/压缩库差异可能改变新打包ZIP本身的SHA，样本archive SHA只标识这次实验。

从零重建必须先执行上方技术候选README的三阶段恢复，再pack。原r1八包合3,357,277,618字节，两层更新170,162,103字节，首轮11场景候选分片166,969,978字节，技术差量11,582,302字节，二进制必要输入合 **3,705,992,001字节**；还需少量脚本/清单与Python zstandard依赖。整仓下载包含图册等额外资料，会比此输入总量更大；已有经校验基线可复用不重复下载。恢复与实验副本建议至少30GB空闲磁盘。不要只下载2.364GB实验包的清单就期待恢复内容。
